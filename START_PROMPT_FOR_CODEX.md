# Стартовый промпт для Codex

Передай Codex этот текст вместе с файлами `PRODUCT_SPEC.md` и `AGENTS.md`.

---

Мы начинаем разработку PWA для совместных накоплений. Источник истины — `PRODUCT_SPEC.md`, постоянные правила — `AGENTS.md`.

Сначала полностью прочитай оба файла и осмотри рабочую папку. До изменений покажи компактный поэтапный план и перечисли только решения или блокеры, действительно требующие моего выбора. Не пытайся построить весь продукт одним большим изменением.

Текущая задача — выполнить этапы 0 и 1: подготовить репозиторий и локальный интерактивный вертикальный прототип на безопасных демонстрационных данных.

Требования:

1. Если папка пуста, создай Next.js App Router проект с актуальными стабильными версиями, TypeScript strict, Tailwind CSS и npm. Не выдумывай номера версий.
2. Настрой ESLint, Prettier, Vitest, Testing Library и Playwright. Добавь scripts `dev`, `lint`, `typecheck`, `test`, `test:e2e`, `build`.
3. Сохрани `PRODUCT_SPEC.md` и `AGENTS.md` в репозитории. Создай краткий `README.md` с точными командами для Windows 11 и `.env.example` без секретов.
4. Реализуй development-only demo data layer через интерфейсы репозиториев. Demo-режим не должен случайно включаться в production.
5. Создай адаптивный русский интерфейс:
   - «Мои цели»;
   - пример «Квартира» с датой 01.04.2027;
   - обзор с суммой, процентом, полоской, остатком, требуемым темпом и вкладом двух участников;
   - накопления с ручным добавлением и редактированием;
   - расходы с ручным добавлением и редактированием;
   - дашборд расходов с категориями, общей суммой, необязательными расходами и «Можно было отложить»;
   - последние действия;
   - нижнюю мобильную и боковую компьютерную навигацию.
6. Следуй палитре и визуальному направлению спецификации. Не используй generic dashboard look, банковский синий, кислотные градиенты, копилки и нефункциональный декор.
7. Централизуй пользовательские строки. Вынеси финансовые расчёты из компонентов в чистые типизированные функции.
8. Храни демонстрационные суммы в minor units. Не используй `float` для финансовой логики.
9. Расход не меняет накопления. «Можно было отложить» содержит только явно необязательные расходы.
10. Пока не подключай Supabase, OAuth, реальные приглашения, импорт файлов, хостинг или платные сервисы. Подготовь границы подключения, но не создавай внешние ресурсы и не запрашивай ключи.
11. Добавь unit-тесты минимум для всех типов накопительных операций, неизменности прогресса от расходов, прогресса 0/100/>100%, истёкшего срока, potential savings и точности minor units.
12. Добавь Playwright smoke-тест основного demo-сценария.
13. Проверь UI на 390 px и 1440 px. Исправь переполнения, подписи и клавиатурный фокус.

Не изменяй продуктовые правила молча. При противоречии укажи конкретные разделы спецификации и предложи безопасный вариант.

Готово, когда `lint`, `typecheck`, unit tests, smoke E2E и production build проходят, прототип запускается по README, а отчёт содержит:

- что создано;
- какие проверки реально выполнены;
- как открыть прототип;
- какие ограничения остались;
- какой один следующий этап рекомендуется.
