# Update 5.1 — manual entry confirmation

- При ручном добавлении накопления кнопка показывает «Добавляю…», а после сохранения — «Добавлено ✓».
- Под кнопкой появляется явное подтверждение, поэтому больше не нужно прокручивать страницу к общей сумме, чтобы понять, сработало ли действие.
- После успешного добавления поля очищаются, а повторное нажатие во время отправки заблокировано.
- Такое же поведение добавлено ручным расходам.
- Миграции Supabase и новые npm-пакеты не требуются.

- Миграции Supabase и новые npm-пакеты не требуются.

# Update 4.8 — duplicate protection

- Перекрывающиеся выписки можно загружать повторно: ранее сохранённые операции будут пропущены, новые — добавлены.
- Защита работает не только для Отбасы/Halyk: импорт остаётся bank-agnostic и применим к Kaspi, Freedom и другим банкам.
- Стабильный ID/Reference/RRN используется автоматически, когда он есть в CSV/XLSX или распознан в PDF.
- Без ID используется fingerprint с учётом количества одинаковых операций, поэтому две реальные одинаковые транзакции не склеиваются.
- Номер банковского счёта не сохраняется: используется только SHA-256 отпечаток, если счёт удалось определить.
- Требуется миграция `supabase/migrations/202609010004_duplicate_protection.sql`.

# Обновление 4.7

Версия приложения: `0.10.0`.

## Что изменилось

- В раскрытом блоке «Накопления» кнопки «Добавить накопление» и «Импортировать файл» находятся сразу под заголовком.
- В раскрытом блоке «Расходы» кнопки «Добавить расход» и «Импортировать файл» находятся сразу под заголовком.
- Списки операций больше не растягивают главный экран цели.
- «История пополнений» открывает отдельную страницу со всеми операциями накоплений.
- «История расходов» открывает отдельную страницу со всеми расходами.
- Истории отсортированы от новых операций к старым и сохраняют действия редактирования/удаления.

SQL-миграции и новые npm-пакеты не требуются.
